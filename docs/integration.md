# TG: как соединить инструкцию таблицы и скиллы контент-машины

Дата: 2026-08-28  
Источник: `TG_контент_инструкция_2026-08-28.zip`  
Статус: схема соединения без правок в таблице и коде

## 1. Что лежит в новом ZIP

Архив описывает рабочую таблицу и ее автоматику.

- `README.md` - объясняет назначение пакета и ссылку на таблицу.
- `01_Быстрый_старт_редактора.md` - утренний маршрут редактора: пульт, план недели, аккаунтные листы.
- `02_Как_работает_машина.md` - логика выбора темы через финансы, маркетинг и календарь.
- `03_Карта_листов.md` - карта рабочих, сигнальных и технических листов.
- `Код.gs` - Google Apps Script для обновления финансов, сигналов, недельного плана, синхронизации IG-листов и защиты ручных правок.

Этот пакет отвечает за таблицу, циклы и техническую синхронизацию.

## 2. Что дают наши скиллы

Наши TG-скиллы отвечают за качество мышления и текста поверх таблицы.

- `tg-content-planner` - собирает из сигнала и рубрики нормальную тему.
- `tg-storyboard` - раскладывает тему в съемочное задание.
- `tg-content-qa` - проверяет тему, факты, метрики, текст и производственную готовность.
- `tg-marketing-orchestrator` - связывает таблицу, папки, роли, статусы, ручное согласование и алерты.

Скиллы не заменяют Apps Script. Apps Script не заменяет скиллы.

## 3. Правильная архитектура соединения

Рабочий порядок:

1. Таблица и Apps Script собирают данные.
2. `02_Сигналы`, `06_Маркетинг`, `03_Календарь года`, `07_Банк идей` дают основания.
3. `08_План недели` показывает автоматический черновик.
4. Редактор смотрит `00_Пульт редактора` и `IG_*`.
5. `tg-content-planner` проверяет, почему тема выбрана, и усиливает формулировку.
6. `tg-storyboard` делает раскадровку для выбранных публикаций.
7. `tg-content-qa` проверяет факты, язык, первый кадр, метрики и риски.
8. Человек подтверждает цену, срок акции, наличие, филиал, доставку и статус публикации.
9. Только после подтверждения материал идет в производство.

## 4. Где сейчас разрыв

В ZIP хорошо описана механика таблицы, но ей не хватает предметного слоя.

Что уже есть:

- финансовые сигналы;
- маркетинговые сигналы;
- календарь;
- банк идей;
- недельный план;
- ручная защита правок;
- синхронизация между `IG_*`, `05_Сводный план` и `08_План недели`.

Чего не хватает:

- рыночных и флористических трендов внутри правил выбора темы;
- правил по конкретным цветам, сезонности и уходу;
- чистого языка без технических англицизмов;
- QA по обещаниям: стойкость, доставка, цена, срок акции;
- связи с папкой раскадровок и исходников;
- отдельного поля для фактов, которые должен подтвердить клиент.

## 5. Что обновить в таблице

Без изменения текущей логики можно добавить слой правил:

- `Трендовый угол` - повседневная покупка, подарок, дом, учитель, сезон, уход, цветовая серия.
- `Факт для проверки` - цена, срок, наличие, филиал, доставка, бронь, состав.
- `Тип первого кадра` - товар с ценой, букет в руках, крупный цветок, сравнение оттенков, человек в действии.
- `Ссылка на раскадровку` - документ или файл задания для съемки.
- `QA статус` - требует факта, готово к съемке, готово к публикации, вернуть на правку.

Если колонок добавлять нельзя, эти значения можно временно писать в `Обоснование`, `Статус обоснования`, `Первый кадр / принцип`, `Источник материала`.

## 6. Что обновить в Apps Script

Код уже делает основную автоматику. Достаточно точечно почистить тексты и метки.

Заменить в автогенерируемых строках:

- технические англоязычные призывы - на "следующий шаг" или "действие клиента";
- англоязычное название прямого канала - на "сообщения аккаунта";
- рекламный жаргон - на "предложение" или "условия акции";
- "маржа" в клиентском слое - на "норма прибыли", если это видит клиент;
- стрелочные формулы - на обычную последовательность через запятые или короткую схему без стрелок.

Важно: если эти слова используются только как внутренние технические метки в коде, менять надо осторожно. Если они попадают в видимые ячейки таблицы, чистить обязательно.

## 7. Что обновить в инструкции редактора

В `01_Быстрый_старт_редактора.md` заменить:

- `payoff` - на "итог сюжета";
- `CTA` - на "действие клиента";
- `A/B-переменная` - на "переменная теста" или оставить как термин только для внутренней команды;
- "что клиент должен прислать" - оставить, это полезное поле;
- "RAW-листы" - расшифровать как технические листы выгрузки.

После этого инструкция станет понятнее для SMM-команды.

## 8. Как соединить с пакетом для коллеги

Коллеге нужно передать два уровня.

Уровень 1. Таблица:

- открыть `00_Пульт редактора`;
- посмотреть `08_План недели`;
- работать в нужном `IG_*`;
- не трогать технические листы;
- ручные правки делать только в разрешенных колонках.

Уровень 2. Скиллы:

- для выбора тем - `tg-content-planner`;
- для съемочного задания - `tg-storyboard`;
- для проверки перед публикацией - `tg-content-qa`;
- для настройки процесса - `tg-marketing-orchestrator`.

## 9. Как это выглядит на теме георгинов

Таблица дает:

- аккаунт Flowers;
- сигнал;
- календарное окно;
- идею из банка;
- формат;
- дату;
- обоснование.

Скилл добавляет:

- конкретный угол: сезонный цветок, букет в руках, дом, учитель, цена;
- первый кадр;
- варианты съемки;
- текст без рекламного мусора;
- список фактов для проверки;
- раскадровку;
- QA перед публикацией.

## 10. Риск передачи

В `Код.gs` есть встроенные реквизиты доступа к источнику данных. Этот файл нельзя отправлять внешнему подрядчику или человеку без права доступа к техническому контуру.

Для коллеги по контент-плану лучше передавать:

- инструкции редактора;
- карту листов;
- схему работы машины;
- TG-скиллы;
- примеры обкатки.

Технический код передавать только тому, кто будет поддерживать Google Apps Script и имеет право видеть доступы.

## 11. Итоговая схема

`TG_контент_инструкция_2026-08-28.zip` - слой таблицы и автоматики.  
`tg-marketing-skills-package` - слой генерации, раскадровки, проверки и процесса.  
Исследовательские файлы по георгинам - предметная база для первого теста.

Соединять надо через `08_План недели` и `IG_*`: таблица предлагает строку, скиллы делают из нее пригодное задание и проверяют перед публикацией.
