## 1. Решение

Макросервис должен работать с уже созданной таблицей Toshkent Gullari. Новая таблица не нужна.

Существующая таблица остается операционным пультом:

- редактор начинает день в `00_Пульт редактора`;
- автоматический черновик появляется в `08_План недели`;
- общий реестр публикаций хранится в `05_Сводный план`;
- аккаунтные планы ведутся в `IG_*`;
- аудитории берутся из `04_Аудитории`;
- правила контента берутся из `06_Правила контента`;
- банк идей и сигналы остаются источниками оснований.

## 3. Как подключить папки к таблице

Папки нужны как хранилище материалов, а таблица остается пультом.

Рекомендуемые поля связи:

```text
Collect URL
Storyboard URL
Source Media URL
Ready Asset URL
Published URL
Result URL
QA Status
Fact Check Owner
Fact Check Status
```

Минимум для запуска:

- `Storyboard URL`;
- `Source Media URL`;
- `Published URL`;
- `QA Status`;
- `Fact Check Status`.

## 4. Правило записи

Автоматика может заполнять:

- черновые будущие строки;
- сигнальные поля;
- обоснование;
- вопросы на проверку;
- ссылки на созданные документы;
- QA-статус.

Автоматика не должна менять:

- строки со статусом `Согласовано`;
- строки со статусом `В производстве`;
- строки со статусом `Опубликовано`;
- ручные комментарии редактора;
- цены, сроки, наличие и филиалы без подтверждения человека.

## 5. Режимы работы агентов

### Collect Agent

Читает `01_Collect` и справочники таблицы. Возвращает недостающие вводные:

- нет цены;
- нет срока акции;
- нет наличия;
- нет филиала;
- нет источников для съемки;
- нет владельца проверки.

### Planner Agent

Читает `00_Пульт редактора`, `08_План недели`, `04_Аудитории`, `06_Правила контента`, календарь и банк идей.

Возвращает:

- усиленную тему;
- задачу;
- аудиторию;
- формат;
- первый кадр;
- обоснование;
- вопросы человеку.

### Storyboard Agent

Читает строку из `05_Сводный план` или `08_План недели`.

Возвращает:

- сценарий;
- раскадровку;
- съемочное задание;
- список реквизита;
- проверку перед публикацией.

### QA Agent

Читает тему, сценарий, текст, ссылку на исходники и факты.

Возвращает:

- вердикт;
- ошибки;
- недостающие факты;
- статус готовности.

Для каждой строки контент-плана должен быть понятен путь:


В таблице это можно связать через ID:

- `A01`, `A02` - аудитории;
- `R01`, `R02` - рубрики;
- `S001`, `S002` - сигналы;
- `I001`, `I002` - идеи;
- `D01`, `D02` - календарные даты;
- `P-YYYY-MM-DD-ACCOUNT-001` - публикация.

## 8. Проверка перед запуском

Перед включением записи в таблицу проверить:

- таблица открывается у всех участников процесса;
- `00_Пульт редактора` показывает свежий запуск;
- `08_План недели` содержит будущие строки;
- `05_Сводный план` синхронизируется с аккаунтными листами;
- ручные правки редактора защищены;
- есть папка `TG_Content_Machine`;
- есть правило именования публикаций;
- есть владелец проверки фактов.

До этой проверки агенты работают в режиме чтения и рекомендаций.
